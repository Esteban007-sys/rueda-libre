Semana 3 · Rueda Nocturna (Tailwind CSS)

} 1 - Prototipo nocturno con Play CDN: Bootstrap vs. Tailwind CSS (MiniReto 1)
• Cómo construí el botón "Inscríbete" en Semana 2 con Bootstrap:
	• Se usaron clases de componente predefinidas del framework:
	  <a href="paginas/reservas.html" class="btn btn-primary rounded-pill fw-bold">
	• Bootstrap aplica automáticamente el relleno, el color de fondo, los bordes, la tipografía y los estados hover/focus a través de la clase base .btn y la variante .btn-primary.

• Cómo construí el botón "Inscríbete" hoy con Tailwind CSS:
	• Se compuso el aspecto visual pieza por pieza combinando utilidades atómicas directamente en el HTML:
	  <a href="#inscripcion" class="inline-block bg-amber-400 text-slate-950 font-semibold px-8 py-3 rounded-full hover:bg-amber-300 focus:outline-hidden focus:ring-2 focus:ring-amber-200 focus:ring-offset-2 focus:ring-offset-slate-900">
	• Cada utilidad controla una única propiedad CSS: visualización (inline-block), fondo (bg-amber-400), texto (text-slate-950, font-semibold), espaciado (px-8 py-3), forma (rounded-full) y estados interactivos (hover:, focus:ring-*).

• Diferencia clave entre un framework de componentes y uno utility-first:
	• Un framework de componentes (como Bootstrap) entrega piezas completas con diseño predefinido (.btn, .card, .navbar); permite avanzar rápido, pero personalizar la identidad visual suele requerir sobreescribir estilos o variables del framework.
	• Un framework utility-first (como Tailwind CSS) no impone componentes cerrados, sino utilidades de bajo nivel que se combinan en el HTML para construir diseños propios desde cero sin pelear con reglas heredadas ni escribir CSS extra.


} 2 - Maquetación Desktop de la landing (Fase 1 · Día 2)
• Arquitectura semántica y contenedor único:
	• Se construyó nocturna/index.html con regiones semánticas (<header>, <main>, <section id="inicio|rutas|como-funciona|inscripcion">, <footer>) y se extrajo el catálogo previo a nocturna/componentes.html para no perder trabajo anterior.
	• Se aplicó un único patrón de contenedor centrado (max-w-6xl mx-auto px-*) en todas las secciones para conservar un eje vertical uniforme de lectura.
	• Bloques implementados: Header con flex (logo, anclas #rutas, #como-funciona, #inscripcion y CTA "Inscríbete" centrados con items-center), Hero, 3 cards de rutas (Luces del Centro, Parques del Río y Cerro Nutibara), sección "¿Cómo funciona?" (4 pasos: Elige tu ruta, Inscríbete, Recoge tu equipo, Rueda), franja de inscripción con formulario accesible y Footer de 3 bloques con flex.
• Justificación técnica: ¿Por qué grid y no flex en "¿Cómo funciona?"?
	• Se eligió CSS Grid (<ol class="grid ...">) sobre Flexbox porque garantiza 4 columnas estrictamente simétricas (1fr por pista) sin que la longitud del texto descompense el ancho, mantiene igual altura de fila automáticamente y facilita escalar de 1 -> 2 -> 4 columnas en mobile-first sin cálculos manuales ni basis-*.

} 3 - Adaptación Responsive Mobile-First (Fase 2 · Día 2)
• Enfoque mobile-first aplicado en nocturna/index.html:
	• Clases base sin prefijo pensadas para móvil (360px) y escalado progresivo con sm: (640px), md: (768px) y lg: (1024px).
	• Header apilado en móvil (flex-col) y en fila desde md: (md:flex-row); navegación oculta en móvil (hidden md:flex) manteniendo siempre visible el botón "Inscríbete".
	• Rutas: grid-cols-1 -> sm:grid-cols-2 -> lg:grid-cols-3.
	• Pasos: grid-cols-1 -> sm:grid-cols-2 -> lg:grid-cols-4.
	• Formulario de inscripción (grid-cols-1 md:grid-cols-3) y Footer (flex-col md:flex-row) adaptados para garantizar 0 px de scroll horizontal a 360px sin depender de overflow-x-hidden.

} 4 - Tema de Marca (@theme), Modo Oscuro (dark:) y Auditoría WCAG AA (Fase 3 · Día 3)
• Configuración de @theme en nocturna/src/input.css:
	• 5 colores base de Rueda Libre: --color-verde-ruta (#1E7A4F), --color-naranja-pedal (#F39A2B), --color-azul-noche (#14213D), --color-crema (#FAF6EF), --color-gris-asfalto (#5B6470).
	• Color de campaña agregado: --color-amarillo-farol (#FFD166).
	• Tipografías de marca: --font-display (Montserrat) y --font-sans (Open Sans), cargadas desde Google Fonts en index.html y componentes.html.
	• Reemplazo del 100 % de colores genéricos de Tailwind (slate-*, amber-*, emerald-*, rose-*, sky-*) por utilidades de @theme (conservando únicamente white en superficies claras).
• Modo oscuro híbrido accesible:
	• Variante dark: configurada en input.css con soporte automático para prefers-color-scheme: dark más botón interactivo (#theme-toggle) con persistencia en localStorage, aria-pressed y color-scheme nativo.

} 5 - Refactorización, Minificación y Comparativa Bootstrap vs. Tailwind (Fase 4 · Cierre Día 3)
• Refactorización controlada (@layer components + @apply):
	• Conteo de repeticiones en index.html: Botón Primario (6 veces, ~88 utilidades repetidas), Botón Secundario (1 vez + catálogo), Botón Terciario (2 veces + catálogo).
	• Se crearon exactamente 3 clases de botón (.btn-primario, .btn-secundario, .btn-terciario) en @layer components de src/input.css; las cards de rutas mantuvieron sus utilidades directamente en el HTML.
	• Todas las clases de index.html y componentes.html se ordenaron estrictamente bajo: 1. Layout -> 2. Espaciado -> 3. Tipografía -> 4. Color -> 5. Estados/Responsive.
• Compilación con Tailwind CLI (--minify):
	• Comando: npx tailwindcss -i ./src/input.css -o ./src/output.css --minify
	• Tamaño medido en disco de nocturna/src/output.css: 36,81 KB minificado (5,69 KB estimado con Gzip).
• Comparativa técnica: Bootstrap 5.3 (rueda-libre) vs. Tailwind CSS v4 (rueda_nocturna):
	1. Curva de aprendizaje:
		• Bootstrap: Baja al inicio gracias a componentes prearmados (.navbar, .card, .btn), pero exige aprender sus variables --bs-* al salir de su estética estándar.
		• Tailwind: Media al inicio (requiere dominio de CSS y memorizar utilidades), pero muy rápida y predecible al dominar su sistema atómico.
	2. Personalización:
		• Bootstrap: Por sobrescritura (~240 líneas en rueda-libre/css/styles.css para adaptar colores, botones y modo noche sobre los estilos base).
		• Tailwind: Nativa por diseño mediante @theme en src/input.css, convirtiendo colores y tipografías de marca directamente en utilidades sin conflictos de especificidad.
	3. Tamaño final (medición real en DevTools -> Network -> CSS con Disable cache):
		• Bootstrap 5.3 + styles.css (rueda-libre): Transferencia [ ___ KB ] | Recurso sin comprimir [ ___ KB ]
		• Tailwind CSS v4 --minify (rueda_nocturna/nocturna/src/output.css): Transferencia [ ___ KB ] | Recurso sin comprimir [ ___ KB ] (en disco: 36,81 KB minificado / 5,69 KB gzip)
	4. Casos de uso:
		• Bootstrap: Prototipos rápidos, paneles internos o proyectos donde la estética estándar del framework y sus componentes JS listos son prioridad.
		• Tailwind: Landings de campaña, productos con identidad visual propia, sitios orientados a rendimiento web y arquitecturas basadas en componentes reutilizables.
• Recomendación técnica para el sitio principal de Rueda Libre:
	• Mantener Bootstrap 5.3 en la versión estable actual de Rueda Libre mientras siga siendo HTML estático multipágina, y adoptar Tailwind CSS v4 para nuevas campañas (como Rueda Nocturna) y para una futura v3.0 cuando el sitio incorpore plantillas o componentes (Astro/React), aprovechando así el sistema @theme validado con WCAG AA y el menor peso en producción sin duplicar HTML manualmente.
